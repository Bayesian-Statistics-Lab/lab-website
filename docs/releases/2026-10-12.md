## 주요 변경

### 논문 편집기의 책임 분리

- 관리자 대시보드와 공개 논문 페이지의 인라인 편집이 같은 전용 `PublicationEditor`를 사용합니다.
- 목록·폼 표시 컴포넌트, 조회·저장·공개 변경·삭제를 조율하는 훅, 요청 모듈, 폼 및 상태 모델을 `features/publications`로 분리했습니다.
- 기존 `AdminEditor`의 논문 진입점은 전용 편집기에 위임합니다. 게시글·구성원·고정 페이지까지 전면 리팩토링한 것은 아닙니다.
- 검색·연도/인용수 정렬·인용수 미상 후순위·전체 선택·초안 생성·기존 요약 유지·인라인 완료/취소 동작을 보존합니다.
- 선택 삭제는 100개씩 순차 처리하며 실제 성공한 ID만 반영합니다. 후속 배치 실패 시 앞서 완료된 삭제와 서버 경고를 유지합니다.

### 구성원 이미지 요청과 저장된 축소본 재사용

- 구성원 목록·상세·조직도는 공용 `MemberPortrait`를 사용합니다. 지원되는 공개 업로드 사진은 `/api/media/…?w=320` 또는 `w=640`으로 요청하여 Next 이미지 최적화 API를 다시 거치는 경로를 줄였습니다.
- 목록의 첫 네 개 공개 사진은 표시 역할 순서대로 먼저 요청하고 나머지는 지연 로딩합니다. 교수·상세 사진은 우선 요청하며 GIF·외부 이미지·기본 그림은 기존 렌더링을 유지합니다.
- 공개 구성원 조회를 화면과 미디어 권한 검사에서 공유합니다. 공개 프로필 사진은 전체 게시글·페이지 참조 검색과 불필요한 서명 URL 발급을 생략합니다. 일반 본문 이미지와 PDF는 기존 공개 참조 확인을 유지합니다.
- 변환 결과를 Next 데이터 캐시의 Base64 대신 private `lab-media`에 바이너리 WebP로 저장합니다. 콘텐츠 캐시 무효화 후에도 저장된 같은 축소본을 다시 읽습니다.
- 최초 변환 결과는 바로 반환하고 응답 후 저장합니다. 저장 실패나 동시 생성 경쟁이 사진 표시를 막지 않으며, 같은 인스턴스의 동일 요청은 공유합니다.
- 공개·본인·관리자 접근 권한을 확인한 뒤 파일을 읽습니다. 저장된 축소본이 있다는 사실만으로 접근을 허용하지 않습니다. 공개 응답/CDN은 60초, 비공개 응답은 `private, no-store` 정책을 유지합니다.
- 변환·저장소 장애 시 원본 스트리밍으로 돌아갑니다. GIF 제한·프레임/재생 보존과 PDF 리다이렉트도 유지합니다.

### 구성원 페이지의 글자·카드·간격

- 교수·구성원 이름과 역할의 영문 표기를 한글 옆 보조 텍스트로 배치했습니다. 화면이 좁으면 자연스럽게 줄바꿈합니다.
- 섹션 제목·역할 제목·이름의 크기를 구분하고 영문 이름의 가독성을 조정했습니다.
- 역할별 구성원이 한 명이면 카드가 본문 너비를 채우며, 여러 명이면 공간에 따라 여러 열로 배치됩니다.
- 카드 안쪽 여백, 역할 및 섹션 간격, 모바일 글자 크기를 조정했습니다. 교수 소개의 중복 영문 역할 문구는 제거했습니다.

### 교수 연구 관심 분야와 관련 링크

- 연구 관심 분야를 사진 아래 별도 섹션에서 사진 오른쪽의 이름·소속·연락처 영역 안으로 옮겼습니다. 구성원 목록과 교수 상세에 모두 적용됩니다.
- 모바일에서는 사진 아래에 소개와 관심 분야가 함께 쌓입니다. 빈 관심 분야 항목은 제외하고 긴 태그는 줄바꿈합니다.
- 기본 ‘교수 개인 홈페이지’ 버튼을 제거했습니다. 관리자 편집 폼의 선택 항목인 ‘관련 링크’를 입력한 경우에만 버튼을 표시하고, 비우면 숨깁니다.
- 새 `professor_details.related_url`은 기본값이 빈 문자열이며 HTTPS URL만 허용합니다. 기존 `website` 값은 호환을 위해 보존하되 공개 버튼에는 사용하지 않습니다. 기존 홈페이지 주소를 계속 연결하려면 관리자가 관련 링크 항목에 명시적으로 입력해야 합니다.

## 업데이트와 운영 확인

1. Node.js 22 이상과 기존 lockfile로 `npm ci`, `npm run build`를 실행합니다. 추가 환경변수·DB SQL·패키지 버전 변경은 없습니다.
2. 기존 Supabase 설정과 private `lab-media`를 유지합니다. 신규 설치 및 계정 삭제·탈퇴에 필요한 SQL 조건은 [README](../../README.md)를 따릅니다.
3. 서버 전용 Storage 읽기·쓰기 권한을 확인합니다. 생성된 축소본은 Storage 용량을 추가로 사용하며 원본과 함께 백업·정리 대상입니다. 기존 삭제·탈퇴 기능이 Storage 파일까지 자동 정리한다고 가정하지 않습니다.
4. 앱 업로드는 새 UUID 경로를 사용합니다. 외부에서 같은 원본 경로를 덮어쓰면 저장된 축소본이 남을 수 있으므로 새 UUID를 사용하거나 해당 생성 파일을 정리합니다.
5. 권한 변경은 캐시가 반영되는 시간이 있습니다. 공개 응답/CDN의 60초 TTL과 서버 공개 정보 캐시를 고려하여 공개 해제·접근 제한을 확인합니다.
6. 교수 편집에서 ‘관련 링크’를 비웠을 때 숨김, 입력·저장 후 연결, 구성원 및 교수 상세의 데스크톱·모바일 배치를 확인합니다.
7. 최신 배포 확인에는 고정 운영 주소를 사용합니다. 특정 배포 URL은 이전 코드를 가리키거나 Vercel 배포 보호가 적용될 수 있습니다. 이미지 404와 응답 지연을 구분하여 확인합니다.

## 검증과 확인 범위

- PR #12의 기능 트리에서 테스트 **136개**, 타입 검사, 프로덕션 빌드가 통과했습니다. 신규 테스트는 편집기 요청·상태·부분 삭제, 이미지 경로·권한·저장 결과 재사용, 관심 분야 위치·관련 링크 조건·URL 검증을 포함합니다.
- 운영 구성원 페이지에서 두 업로드 사진의 직접 미디어 요청과 정상 표시, 공개 미디어의 CDN `HIT`를 확인했고 사용자도 정상 열림을 확인했습니다.
- 진단 환경에서 첫 연결의 TLS 수립 지연이 관찰됐으므로 전체 HTTP 시간을 서버 처리 시간으로 해석하지 않습니다. 모든 사용자·기기의 초기 로딩 시간이나 정량 개선율을 보장하지 않습니다.
- PR #10~#12의 변경된 배치는 코드·빌드 검사 범위이며 실제 운영 화면의 데스크톱·모바일 시각 검증 완료를 뜻하지 않습니다.
- 저장된 축소본이 없는 첫 요청은 원본 읽기와 변환이 필요합니다. 응답 후 Storage 저장이 실패하면 이후 요청에서 다시 변환할 수 있습니다. 비공개 파일의 공개 버킷 전환은 하지 않았습니다.

## 롤백과 보관

코드 문제는 이전 검증 커밋을 재배포하여 롤백합니다. 이번 변경은 기존 DB 스키마와 원본 이미지에 대한 마이그레이션이 없으며, 생성된 WebP 파일과 `related_url` 설정 데이터는 코드 롤백만으로 삭제되지 않습니다. 이전 코드에서는 새 관련 링크 항목이 표시되지 않을 수 있습니다.

소스 ZIP/TAR는 DB·Storage·환경변수를 포함하지 않습니다. 데이터와 서버 설정은 별도로 백업해야 합니다. 유지보수 구조와 보존 계약은 [리팩토링 문서](../REFACTORING.md)를 참고하세요.
