## 사용자에게 달라진 점

### 가입과 계정

- 이메일 확인 링크 대신 가입 신청 후 관리자 승인을 기다립니다. 승인 전에는 본인 프로필 관리, 승인 후에는 구성원 공개·허용 게시판 작성·본인 글 관리가 가능합니다.
- 과거 인증 대기 신청도 관리자 승인 시 로그인 설정을 처리합니다.
- 같은 IP에서 다른 이메일로 가입해도 각각 요청 제한을 적용합니다. 동일 조합은 1분에 5회이고 제한 시 남은 초를 안내합니다.
- 현재 상태에 맞춰 승인 또는 승인 해제 버튼 하나를 표시합니다.
- 본인 탈퇴에는 비밀번호와 명시적인 동의가 필요합니다.

### 삭제와 권한

- 구성원 삭제 시 연결된 로그인 계정·가입 정보도 제거해 프로필 자동 복구로 다시 생성되는 문제를 보완했습니다.
- 가입 승인 목록에서 과거 프로필만 제거된 계정도 삭제합니다.
- 관리자 삭제 API, 본인 대상 ID, 서버 전용 삭제 RPC와 관리자·소유자 보호를 적용했습니다.
- 연결 계정·프로필 삭제는 DB 트랜잭션으로 처리합니다. 기존 게시글·논문 원본은 유지하며 Storage 파일 일괄 삭제·작성자 표시 문자열 익명화는 포함하지 않습니다.

### 홈페이지와 관리 UI

- 홈 배너 이미지/GIF와 업로드 안내, 연구 분야 카드 1~3개 설정을 제공합니다. 홈은 이미지 위·내용 아래, 연구 분야는 이미지 왼쪽·설명 오른쪽 배치입니다.
- 고정 본문, 구조화된 날짜순 연혁, 랩장·역할별 조직도, 교수 소개·이력과 Alumni 정보를 관리합니다.
- Tiptap 사진 삽입, 게시판 작성자·날짜·순번, 게시판/갤러리 페이지 크기 선택과 이동을 제공합니다.
- 마이페이지 사진·인적사항 배치, 프로필/내 글 뷰 전환, 아이디 저장과 계정 메뉴를 정리했습니다.
- 논문 공개 토글, 인용수 정렬, 선택 삭제와 제공된 요약·학술지 표시를 제공합니다. 상세 화면의 중복 제목 부제는 제거하고 요약은 유지합니다.

### 모바일 반응형 보완

- 900px 이하에서 관리자 메뉴를 선택 목록으로 제공하며 기존 본문 뷰 전환과 브라우저 뒤로 가기를 유지합니다.
- 홈페이지 하위 메뉴를 여러 줄로 표시하고 현재 항목을 구분합니다.
- 대시보드 제목·이메일, 관리 목록, 폼·버튼·표의 작은 화면 가로 넘침을 조정했습니다. 380px 이하에서는 통계 카드를 한 열로 표시합니다.

### 연혁과 GIF 배너

- 날짜 표기가 달라도 같은 연·월의 연혁을 하나의 날짜 노드로 묶고 이력을 하위 항목으로 나열합니다. 내용은 모두 유지하며 최근 월을 먼저 표시합니다.
- 관리자 폼에 그룹별 ‘+ 이력 추가’를 제공합니다. 기존 중복 항목은 공개 화면에서 즉시 묶고 다음 저장 시 묶음 구조를 저장합니다. 별도 DB 마이그레이션은 필요하지 않습니다.
- GIF 정지·재생 버튼을 제거했습니다. GIF는 기본 자동 재생이며 기기의 모션 감소 설정에서는 정적 대체 이미지를 표시합니다.

## 설치·업데이트 조건

1. Node.js 22 이상에서 `npm ci`로 설치합니다.
2. README의 Supabase·SerpApi·Cron 환경변수 5개를 설정합니다. 서버 키를 공개 환경변수로 사용하지 않습니다.
3. 신규 DB에는 001 → 002 → 003 → 004 SQL을 적용합니다. 기존 DB에는 미적용 SQL만 실행하며 001은 초기 설치용입니다.
4. **계정 삭제·탈퇴는 004_account_withdrawal.sql이 필수**입니다. 미적용 시 오류를 반환하며 코드 배포가 SQL을 설치하지 않습니다.
5. private `lab-media`, 이메일/비밀번호 로그인과 최초 관리자 `profiles` 등록을 확인합니다. 새 웹 가입에는 메일 템플릿 변경이 필요하지 않습니다.

세부사항은 [README](../../README.md)와 [가입·프로필 안내](../AUTH_AND_PROFILE.md)를 참고하세요.

## 성능 관련 구현

공개 데이터는 3600초 캐시하고 저장 시 `lab-public` 태그를 무효화합니다. 세션 UI 조회를 공유하고 독립 서버 조회는 가능한 곳에서 병렬로 실행합니다. 파일 본문은 Vercel을 중계하지 않고 Storage로 직접 전송합니다. 공개 미디어는 구성원·게시글·페이지 참조를 모은 60초 공유 캐시와 동시 초기 조회 공유를 사용합니다. 기존 이미지별 5개 DB 조회를 공유 참조 인덱스로 통합하고 페이지 단위로 조회해 DB 기본 반환 개수에 잘리지 않도록 했습니다. 이미지별 서명 URL 캐시는 유지합니다. 공개되지 않은 객체는 관리자 또는 본인 경로 권한을 확인합니다.

배너를 높은 우선순위로 요청합니다. 사이트 내 JPG/PNG/WebP 배너·연구 카드에는 `next/image`의 크기별 이미지 제공을 적용하고 최소 캐시 TTL은 60초로 설정했습니다. GIF·SVG·외부 이미지, 계정·편집 미리보기에는 이 변환을 적용하지 않습니다. 업로드 압축과 직접 전송은 유지합니다. 배포 리전은 `icn1`입니다.

이는 구현 설명이며 실제 로딩 시간 개선율이나 전송 속도 보장 수치는 아닙니다.

## 검증 결과와 한계

- 전체 단위 테스트 **57개 통과**: 권한·입력·가입 제한·구성원 연결/삭제·게시판/갤러리 계산·미디어·리치 텍스트·Scholar/설정 처리, 동일 월 병합·다수 이력 보존, 공개 이미지 참조 판별 등.
- 기능 기준 커밋의 타입 검사·프로덕션 빌드 및 Vercel 배포 성공 확인.
- 공개 화면에서 이메일 인증 없는 가입 신청 안내 확인.
- 운영 연혁에서 같은 월의 두 항목이 한 날짜 아래 표시되고, 홈 배너의 높은 요청 우선순위가 반영된 것을 확인.
- 주요 기능 변경과 GIF 버튼 제거 커밋의 Vercel Production `Ready` 확인.

실제 모바일 기기의 관리자 화면과 이미지 최적화 전후 속도·첫 변환 시간은 측정하지 않았습니다. 홈에서 확인한 현재 이미지는 SVG이며 업로드한 정적 사진의 변환 결과까지 검증한 것으로 해석하지 않습니다.

운영 DB의 실제 SQL 적용, 신규 계정 생성 → 승인 → 공개, 실제 탈퇴·계정 삭제, 파일 전송과 외부 Scholar 전체 흐름은 위 결과만으로 검증 완료를 주장하지 않습니다. 실제 사용자 계정을 검증 목적으로 삭제하지 않았습니다.

운영 확인은 승인 전후 권한·사진 공개 범위·게시글 관리·논문 공개/삭제를 점검합니다. 파괴적인 삭제 검증은 별도 테스트 DB의 폐기 가능 계정을 사용합니다.

## 알려진 제한과 다음 유지보수

- Scholar 전체 페이지 순회·대량 큐·BibTeX 영구 보관 및 운영 모니터링은 후속 작업입니다.
- UI·API·CSS에 긴 파일과 중복 처리가 남아 있습니다. 문서·포맷 → 관리자 UI 분리 → 콘텐츠 API 분리 순으로 진행하고 DB·캐시·쿼리·의존성 변경과 분리합니다.

문제 발생 시 이전 검증된 Git 커밋으로 다시 배포할 수 있습니다. **이미 삭제한 계정·프로필은 코드 롤백으로 복구되지 않습니다.** DB 함수 변경에는 기존 함수 정의·데이터 백업과 별도의 복구 절차가 필요합니다.
