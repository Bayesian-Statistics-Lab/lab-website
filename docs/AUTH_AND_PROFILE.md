# 가입·관리자 승인·프로필·계정 삭제 운영 안내

2026-10-10 구현 기준입니다. 과거 이메일 인증 템플릿·콜백 설정 안내를 대체합니다.

## 가입과 승인

1. 사용자는 `/register`에서 이메일·비밀번호·이름·역할·소속 정보를 입력합니다.
2. `/api/registration/signup`이 서버 전용 키로 Auth 계정을 생성합니다. `email_confirm: true`를 사용하므로 확인 메일이나 링크 클릭 절차가 없습니다.
3. 새 프로필은 `role='viewer'`, `membership_status='pending'`이고 구성원은 비공개입니다. Auth 이메일 확인 필드는 관리자 승인 여부를 뜻하지 않습니다.
4. 승인 전에도 로그인하여 본인 프로필·사진을 관리합니다. 게시글 작성과 공개 구성원 등록은 허용하지 않습니다.
5. 관리자는 `/admin?view=membership`에서 승인합니다. 승인 완료에는 승인 해제만, 대기·미승인에는 승인만 표시합니다.
6. 승인 후 구성원 공개와 소식·학술활동·행사 글 작성·본인 글 관리가 활성화됩니다. 승인 해제는 계정을 유지하고 공개·작성 권한을 해제합니다.

과거 인증 미완료 신청은 관리자 승인 API가 Auth 로그인 설정을 처리한 뒤 승인 RPC를 실행합니다. `/auth/callback`은 가입 안내를 표시합니다. 메일 템플릿은 새 웹 가입의 필수 설정이 아닙니다.

사이트 권한은 `profiles.role`, 승인 상태는 `profiles.membership_status`, 구성원 구분은 `members.role`로 구분합니다. Postdoc/Researcher는 실제 구분을 `lab_role`과 구성원 행에 반영하고 기존 학위 제약에는 호환 값을 사용합니다. 역할 선택은 관리자 권한을 부여하지 않습니다.

## 누락된 구성원 연결

`ensureMemberApplication`은 누락된 신청·구성원 행을 보완합니다. 기존 행과 승인 상태를 덮어쓰지 않으며 신규 신청은 승인 대기로 생성합니다. 기존 승인 계정의 누락 프로필은 그 승인 상태를 따르므로 **연결된 구성원을 삭제할 때 계정도 함께 제거**해야 합니다.

## 삭제와 탈퇴

| 작업 | 처리 |
| --- | --- |
| 관리자 구성원 삭제 | 연결된 계정·신청·프로필을 함께 삭제 |
| 가입 승인 목록의 계정 삭제 | 과거 프로필만 삭제한 계정을 포함하여 계정·신청·프로필 삭제 |
| 계정 없는 수동 구성원 삭제 | 프로필·관련 소개 설정 삭제 |
| 본인 탈퇴 | 현재 비밀번호와 동의 확인 후 계정·신청·프로필 삭제 |
| 승인 해제 | 계정 유지, 구성원 공개·게시글 작성 권한 해제 |

`supabase/004_account_withdrawal.sql`의 `withdraw_lab_account`가 연결된 계정 정보를 한 트랜잭션으로 삭제합니다. 서버 `service_role`만 호출하며 관리자·소유자 계정을 보호합니다. 본인 탈퇴 API는 세션 사용자 ID를 사용하고 다른 사용자 ID를 입력받지 않습니다. 관리자 삭제 API는 관리자 역할을 검증합니다.

기존 게시글·논문 원본은 유지하고 작성 계정 및 구성원 논문 연결을 해제합니다. Storage 객체의 일괄 영구 삭제와 작성자 표시 문자열 익명화는 포함하지 않습니다. 사이트 UI에서 삭제를 복구할 수 없으며 백업 복구는 별도입니다.

004 미적용 시 계정 삭제/탈퇴 API는 오류를 반환합니다. 함수 설치만으로 기존 계정이 삭제되지는 않습니다. 신규 설치는 001 → 002 → 003 → 004 순서이며 기존 DB에는 미적용 파일만 실행합니다.

## 본인 사진과 공개 정보

- `members.user_id`와 로그인 계정 연결이 필요합니다. 관리자에게 다른 사람의 프로필을 자동 연결하지 않습니다.
- `/api/account/photo`가 발급한 본인 경로로 Storage에 직접 업로드합니다.
- JPG/PNG/WebP, 최대 5MB를 지원하고 경로 소유자·크기·MIME·파일 시그니처를 확인합니다.
- 사진 초기화는 참조를 비우며 Storage 파일을 영구 삭제하지 않습니다.
- 미승인 사진은 본인 로그인 경로 또는 관리자 권한으로 접근합니다. 공개 콘텐츠에서 참조한 미디어는 공개 접근이 가능합니다.
- 학번·연락처·로그인 이메일은 사용자가 선택한 공개 범위에 따라 반영합니다. 공개 소속 정보는 별도 페이지 설정에 저장합니다.

## 요청 제한과 문제 확인

가입 요청은 유효한 입력에 한해 서버 인스턴스별 IP+이메일당 1분에 5회 제한합니다. 다른 이메일은 별도 카운터이며 성공 시 초기화합니다. 제한 시 남은 초와 `Retry-After`를 반환합니다. 여러 인스턴스가 공유하는 지속적인 제한은 아닙니다.

| 증상 | 확인할 내용 |
| --- | --- |
| 가입 신청 연결 오류 | Supabase 주소·서버 키·001~003 SQL |
| 승인 후 구성원 미표시 | 승인 상태, `members.user_id`, `is_visible`, 승인 API 오류·캐시 갱신 |
| 삭제된 구성원이 다시 생성됨 | 과거 프로필만 삭제했는지 확인하고 가입 승인 목록에서 계정 삭제 |
| 탈퇴/계정 삭제 실패 | 004 함수 적용, 서버 키, 보호된 관리자·소유자 여부 |
| 동일 이메일 중복 신청 | 로그인 또는 관리자에게 기존 신청 상태 확인 |

운영 확인은 승인 대기 → 승인 → 승인 해제 권한과 사진 공개 범위를 점검합니다. 삭제 검증은 별도 테스트 DB의 폐기 가능 계정을 사용합니다. 배포·단위 테스트 통과가 실제 SQL 적용과 사용자 연동 검증의 완료를 뜻하지는 않습니다.
